Career operating system  ·  United States + India

The job search runs on evidence, not adjectives.

CareerOS reads a posting in any field, checks it against your actual work authorization, ranks it by deadline before score, and assembles a résumé only from facts you have personally verified. Where it is unsure, it says unknown — it does not guess on your behalf.

01 — The chain

Nothing is evaluated out of order.

A job is not a match until the steps before it have cleared. Country decides which rulebook applies; the rulebook decides whether you can legally hold the role at all; only then does skill overlap mean anything. Each stage below is a real module, and each one can stop the chain.

    03 — Evidence

    A résumé is a query over verified facts.

    Your history is stored as atomic facts — a project, a technology, a responsibility, an achievement, an employer, a date range — each one marked verified by you or not. A tailored résumé is assembled by selecting from that set, never by writing prose about you.

    Before any résumé can be marked final, a checker re-derives every entity in the finished text and matches it back to the evidence that supports it. The checker never calls a model; it is arithmetic over sets, so it cannot be talked around. A claim with no supporting evidence fails the document.

    The consequence shows up as omissions. If a posting wants SAP Firefighter and nothing in your evidence supports it, the requirement is simply left unclaimed — visible to you, absent from the résumé.

    04 — Authorization

    Silence is never read as a yes.

    Work authorization is decided by a country pack — a plain data file of statuses and the phrases that signal them — applied to the posting's own words. It is not a model output, and the agent has no tool that can set it.

    If a posting says nothing about sponsorship, the verdict is unknown, not "probably fine". Every verdict quotes the phrase it was drawn from, and every verdict carries the same disclaimer, because none of this is legal advice.

    Adding a country means adding a YAML file. The United States pack carries 13 authorization statuses; India's carries its own employment and salary conventions, down to reading ₹ LPA as an annual figure.

    05 — Coverage

    No job category is written into the code.

    The 15 seeded domains are a prior, not a schema. A posting that matches none of them well enough — below a confidence floor of 0.18 — is classified into a domain the model names itself, and stored under that new identifier. Nothing in the pipeline needs to know the list in advance.

    ATS keywords are derived per posting from that posting's own text. There is no industry word list anywhere in the repository, which is exactly why a veterinary role and a quantitative trading role both work without anyone adding them.

    07 — Running it

    The demo is frozen. The system is not.

    Everything above is captured output. To run the real thing — live job sources, a real agent loop, Gmail drafts that wait for your approval — clone the repository and start the API. It works with no model key at all; the key only turns on the agent and the LLM classifier.
