Career operating system  ·  United States + India

The job search runs on evidence, not adjectives.

CareerOS reads a posting in any field, checks it against your actual work authorization, ranks it by deadline before score, and assembles a résumé only from facts you have personally verified. Where it is unsure, it says unknown — it does not guess on your behalf.

01 — The chain

Nothing is evaluated out of order.

A job is not a match until the steps before it have cleared. Country decides which rulebook applies; the rulebook decides whether you can legally hold the role at all; only then does skill overlap mean anything. Each stage below is a real module, and each one can stop the chain.

    03 — Where the jobs come from

    Every board, by a route it actually permits.

    Twenty-five providers, declared as data. Google Jobs returns LinkedIn, Indeed, ZipRecruiter, Glassdoor, Monster, CareerBuilder and Dice listings in one query, each naming its origin — which is kept as the job's board, so per-board conversion analytics still mean something. Google Search reaches the Workday, Taleo and iCIMS pages no aggregator carries, reading each posting from the schema.org block the employer publishes for exactly that purpose.

    Then the open developer APIs — Adzuna and Jooble cover both the United States and India — the partner APIs, the RSS feeds, and the per-employer board APIs for a company you are specifically targeting. Four work with no key at all.

    Four boards are registered and refused. LinkedIn, Indeed, Glassdoor and Naukri forbid automated collection and sit behind bot protection; getting past either is the one thing this system will not do. They stay first-class entries so the screen can name the board, give the reason, and point at what carries its postings — a board missing from your list is never a mystery. Naukri is the one that costs real coverage in India, and it says so.

    Provider states

    Enforced, not documented

    A 401, 403, 429 or CAPTCHA page raises and blocks that host for the run. There is no retry with different headers, no rotation, nothing that solves anything — the refusal is the whole response.

    Free-web page fetches check robots.txt first. An API called with your own key does not: that is a sanctioned client, not a crawler.

    04 — Signing in

    Your email is the account. There is no password.

    Two ways in: Google's consent screen, or a six-digit code emailed to the address. The user table has no password column, there is no hashing anywhere, and no route accepts one — a test asserts the absence rather than trusting it. The rule was never to request or store mail credentials, and the cheapest way to keep a promise like that is to have nowhere to put one.

    Google is the authorization-code flow with PKCE, and identity comes from Google's userinfo endpoint called with a token this server fetched itself — so there is no ID token to verify and no crypto dependency. email_verified is checked: an unverified address is not an identity. One consent can cover Gmail too, read and draft only, so connecting your mail signs you in at the same time.

    Emailed codes are stored as a hash salted with the address, capped at five attempts, single-use, and expire in ten minutes. Sessions are signed with a secret generated once at 0600 outside the database, so a database backup cannot mint one.

    Sign-in surface

    Sign-in turns itself on as soon as a method is configured. With neither, the API stays open — the single-user localhost case — rather than locking a door with no key.

    05 — Evidence

    A résumé is a query over verified facts.

    Your history is stored as atomic facts — a project, a technology, a responsibility, an achievement, an employer, a date range — each one marked verified by you or not. A tailored résumé is assembled by selecting from that set, never by writing prose about you.

    Before any résumé can be marked final, a checker re-derives every entity in the finished text and matches it back to the evidence that supports it. The checker never calls a model; it is arithmetic over sets, so it cannot be talked around. A claim with no supporting evidence fails the document.

    The consequence shows up as omissions. If a posting wants SAP Firefighter and nothing in your evidence supports it, the requirement is simply left unclaimed — visible to you, absent from the résumé.

    06 — Authorization

    Silence is never read as a yes.

    Work authorization is decided by a country pack — a plain data file of statuses and the phrases that signal them — applied to the posting's own words. It is not a model output, and the agent has no tool that can set it.

    If a posting says nothing about sponsorship, the verdict is unknown, not "probably fine". Every verdict quotes the phrase it was drawn from, and every verdict carries the same disclaimer, because none of this is legal advice.

    Adding a country means adding a YAML file. The United States pack carries 13 authorization statuses; India's carries its own employment and salary conventions, down to reading ₹ LPA as an annual figure.

    Unknown Sponsorship not mentioned
    We are unable to provide visa sponsorship for this position. Drawn from the posting · verdict: not compatible · AI assessment — verify with employer/recruiter.

    07 — Coverage

    No job category is written into the code.

    The 15 seeded domains are a prior, not a schema. A posting that matches none of them well enough — below a confidence floor of 0.18 — is classified into a domain the model names itself, and stored under that new identifier. Nothing in the pipeline needs to know the list in advance.

    ATS keywords are derived per posting from that posting's own text. There is no industry word list anywhere in the repository, which is exactly why a veterinary role and a quantitative trading role both work without anyone adding them.

    Seeded domains — extended at runtime

    Highlighted domains appear in the demo set. Plus anything else a posting turns out to be — one role here lands in other on purpose.

    09 — Running it

    The demo is frozen. The system is not.

    Everything above is captured output. To run the real thing — live job sources, a real agent loop, Gmail drafts that wait for your approval — clone the repository and start the API. It works with no model key at all; the key only turns on the agent and the LLM classifier.
